# PnPXAI licensing inventory: attribution methods from participating institutions

Status on 2026-11-16. pnpxai `main` is at commit `8b81aeb` (2025-12-18) and the latest PyPI release is 0.1.4 (2025-11-18). Commit hashes given for original repositories are the heads of their default branches on 2026-11-16.

This inventory records what the repositories, package files and public metadata show. It is not legal advice. Agreements between the institutions, such as the consortium agreement for the IITP project, were not available and may already grant some of the permissions discussed here. Wherever the evidence does not settle a point, the cell says **To be confirmed**, and section 3 gathers those points with the evidence and a contact.

To update the inventory, edit the method's row and its entry in section 3 when a license is added or a permission is obtained, and link the evidence, such as the LICENSE file or the written permission. When a release is prepared, re-check the commit hashes and the list of open pull requests.

## 1. Summary

- **Only one of the eight methods has a licensed original repository.** MA-GIG is MIT. The official repositories of RAP, AE, CoIBA, UCAG, LEAR, FreeMCG and MAD-AD (the method behind MadXai) give no license for the method's own code. A public repository without a license grants no permission to copy, modify or redistribute its code, so each of these needs written permission from its authors or a license added to the repository.
- **RAP is the most pressing case.** Code adapted from the unlicensed official repository has been distributed with pnpxai on GitHub since 2023 and in every PyPI release.
- **AE, CoIBA and UCAG are not merged yet** (pull requests #178, #180, #181), so their permissions can be settled before they ship.
- **LEAR, FreeMCG and MadXai download code and weights when they run**, from Hugging Face repositories that pnpxai does not pin to a revision. LEAR's repository has no license. MadXai's is labelled MIT but consists of copies of unlicensed MAD-AD code.
- **The Apache-2.0 / MIT discrepancy is still present.** `configs.ini` on `main` and all five PyPI releases declare MIT, while `LICENSE`, the README, the docs and the license file bundled in each release are Apache-2.0. Section 4 has the details and related issues.
- No attribution method developed by Seoul National University, Sogang University or ETRI was found in the repository or in open pull requests. Sogang and ETRI contribute use cases that depend on their own code (section 2.3).

## 2. Inventory

Terms used in the "Integration" column:

- **Copied:** the same code.
- **Adapted:** original code restructured or partly rewritten.
- **Reimplemented:** new code that follows the original algorithm.
- **External:** not in pnpxai; downloaded or installed separately.

"Lines shared" is the share of substantial code lines in the pnpxai file that also appear verbatim in the original repository. It is a rough indicator, because renamed or restructured code does not match.

Explainers that only wrap third-party libraries (Captum, zennit, attention rollout) are outside this inventory, except where section 5 notes them.

## 4. pnpxai's own license metadata

### 4.1 Apache-2.0 or MIT

The discrepancy is still present.

| Where | What it says | Evidence |
| --- | --- | --- |
| [LICENSE](https://github.com/OpenXAIProject/pnpxai/blob/main/LICENSE) | Apache-2.0 | Full license text. Line 189: "Copyright 2024 PnP XAI Project Team at Statistical Artificial Intelligence Lab at KAIST". |
| `README.md` line 173, `docs/index.md` line 243 | Apache-2.0 | "PnP XAI is released under Apache license 2.0." |
| GitHub's license detection | Apache-2.0 | Repository metadata. |
| `configs.ini` line 18 | **MIT License** | `setup.py` reads this value (line 100) and passes it to `setup(license=...)` (line 225). |
| PyPI metadata of releases 0.1.0, 0.1.1, 0.1.2, 0.1.3 and 0.1.4 | **MIT License** | `License: MIT License` in every wheel and source archive. No license classifiers. |
| License file bundled in every wheel and source archive | Apache-2.0 | `License-File: LICENSE`. |

Every published release therefore contradicts itself: its metadata says MIT and the license file inside it is Apache-2.0. All 16 upstream branches have the same MIT value, and no open pull request changes `configs.ini` or `setup.py`. Metadata of published releases cannot be edited, so the fix needs a corrected `configs.ini` and a new release.

The MIT value is a leftover. `configs.ini` and `setup.py` derive from the packaging files of the `caer` project, which is MIT-licensed: `configs.ini` still has caer's `lib_path = caer` and `git_branch = master`, and 68% of the lines of `setup.py` match caer's.

### 4.2 Related issues

1. **Packaging template without notice.** The caer files above are MIT-licensed, and pnpxai carries no notice for them.
2. **No license classifiers.** `setup.py` sets no trove classifiers and no SPDX license expression, so tools that read classifiers see no license.
3. **Source archives cannot be built.** The source archives on PyPI omit `configs.ini` and `tools/requirements.txt`, both of which their `setup.py` reads. The wheels are unaffected.
4. **Three copyright holder names.** `LICENSE` names the "PnP XAI Project Team at Statistical Artificial Intelligence Lab at KAIST", `configs.ini` says "Team SAIL", and `pnpxai/_meta.py` says "Open XAI PnP". There is no NOTICE file, and no source file has a license header.
5. **No release tags.** The repository has no git tags, so a PyPI release cannot be tied to a commit. That makes it impossible to say exactly which version of a method each release contains.
6. **No notices for adapted code.** RAP's rule code and the packaging template carry no notice of their origin. PR #180 would add the first one.
7. **Datasets in the repository.** `tutorials/data/ImageNet/samples/` holds 1,000 ImageNet images. ImageNet's terms of access limit use to non-commercial research and education, and allow sharing only with colleagues who accept the same terms. `tutorials/data/UCR/` holds the UCR `TwoLeadECG` data. Neither is in the PyPI package. **To be confirmed.**
8. **Unpinned run-time downloads.** LEAR, FreeMCG and MadXai fetch the latest revision of their Hugging Face repositories, so the code that runs, and its license, can change after a release.
9. **LGPL dependency.** `zennit` (LGPL-3.0) is a required dependency for the LRP explainers. pnpxai imports it and extends its classes in `pnpxai/explainers/zennit/` and `pnpxai/explainers/attentions/rules.py`. Those files share 7% and about 20% of their lines with zennit, mostly method signatures and API calls, with at most five consecutive lines. **To be confirmed** that this counts as use of the library and not as copied code.
