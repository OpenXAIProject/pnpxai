| | |
| --- | --- |
| **Class** | `pnpxai.explainers.MadXai` |
| **Category** | Perturbation-based (`PERTURBATION_BASED_EXPLAINERS` in `pnpxai/explainers/__init__.py`) |
| **Backend** | `custom` — MAD-AD masked latent diffusion (UNet, VAE and `diffusion_x0` sampler loaded from the Hugging Face repo `kaistpnp/madical_pnpxai`). |
| **Explanation type** | `attribution`, non-negative (higher = more likely lesion). |
| **Supported modules** | `[]` — the method does not read any module of a classifier, so the recommender cannot match it to an architecture. It is constructed directly. |
| **Modalities** | Image · TimeSeries (membership inherited from `AVAILABLE_EXPLAINERS`; `TextModality` lists explainers explicitly and does not include it). The method is only meaningful for single-channel brain MRI slices (axial, skull-stripped, 256×256); a time-series input fails in the VAE. |
| **Model constraints** | No classifier is used: the explained quantity is "where does this slice deviate from a healthy brain", estimated by the MAD-AD model trained on healthy T2 slices. The bundled weights expect T2-weighted slices registered to MNI-152, skull-stripped, intensities scaled to [-1, 1] with background at -1. Other modalities need MAD-AD weights trained on that modality (`model_config`, `hf_repo`). |
| **Input** | `Tensor(B, 1, H, W)` float in [-1, 1] (or `(1, H, W)`), any device; moved to `model_device` internally. `targets` is accepted and ignored. Tuple inputs are not supported. |
| **Output** | `Tensor(B, H, W)` (or `(H, W)`), `float32`, non-negative and in [0, 1], on the input's device. Already single-channel, so no channel to pool. |
| **Hyperparameters** | `ddim_steps: int = 10` — reverse steps per pass; must not exceed the 10 diffusion steps the model was trained with.<br>`n_samples: int = 32` — stochastic normal counterparts per input; Dice saturates around 16–32, cost is linear.<br>`eta: float = 1.0` — DDIM stochasticity in [0, 1]; 0 makes all samples identical (then use `normalization='none'`).<br>`mask_threshold: float = 0.9` — a latent patch is regenerated when the model's p(normal) is below this; the original MAD-AD sampler uses 0.5. Higher regenerates more tissue (0.5 → 2 %, 0.9 → 12 % of patches at the last step); 0.99 collapses (dev max-Dice 0.60).<br>`n_iters: int = 2` — reverse passes, each started from the previous output latent; 3 gave no further gain.<br>`normalization: str = 'uncertainty'` — residual divided by the per-pixel std of the counterparts plus `eps`; `'none'` uses the raw residual.<br>`sign: str = 'abs'` — `'pos'`/`'neg'` keep only pixels brighter/darker than the counterpart; `'pos'` assumes hyperintense lesions (true for T2/FLAIR tumours, false in general) and is not the default.<br>`eps: float = 0.05` — std floor in [0.01, 0.2].<br>`clip: float = 2.0` — scores clipped to [0, clip] then divided by clip.<br>`sigma: float = 5.0` — final gaussian smoothing in pixels.<br>`seed: int = None` — seeds a generator created at the first call and reused afterwards (one noise stream over a dataset, same as `torch.manual_seed(seed)`); `None` uses the global torch RNG.<br>`model=None`, `vae=None`, `diffusion=None`, `model_config=None`, `model_device=None` — pass all three models to skip the Hugging Face download.<br>`forward_arg_extractor=None`, `additional_forward_arg_extractor=None` — accepted for API compatibility and unused: the whole input tensor is the image.<br>`MadXai.legacy_config()` returns the 0.1.x behaviour (`n_samples=1, eta=0.5, mask_threshold=0.5, n_iters=1, normalization='none', clip=0.25`). |
| **Tunables** | `mask_threshold` → `float(low=0.5, high=0.95, step=0.05)`<br>`eps` → `float(low=0.01, high=0.2, log=True)`<br>`sigma` → `float(low=1.0, high=9.0, step=1.0)` |
| **Injected defaults** | Accepts `forward_arg_extractor` and `additional_forward_arg_extractor` (unused). Does not accept `baseline_fn`, `feature_mask_fn` or `layer`; `AutoExplanation` skips them silently, which is correct because the method has no baseline, feature mask or layer. In practice `AutoExplanation` never builds MadXai (empty `SUPPORTED_MODULES`). |
| **Post-processing** | Output is already pooled and normalized: use `identity` pooling and `identity` normalization (`channel_dim` is irrelevant). Sum-type pooling would sum over the image height. `minmax` per image would destroy the global threshold that max-Dice relies on. |
| **Metrics** | MuFidelity ✗ · AbPC ✗ · MoRF ✗ · LeRF ✗ · Sensitivity ✗ — all five perturb the input and read a classifier's output; MadXai has no classifier. Complexity ✓ — reads the attributions only; measured 0.769 (legacy 0.579, lower is sparser). The algorithm is evaluated by lesion localization against ground truth masks: max-Dice (threshold searched over 201 values in [0, 1], mean over slices), pixel AUROC, pixel AP. |
| **Cost** | `n_samples × n_iters × ddim_steps` UNet passes per slice (640 with defaults) plus `n_samples + 1` VAE decodes; no backward passes. Measured: RTX 4090, batch 8, 1.81 s/slice, peak 3.0 GiB (`python tutorials/mad_xai.py --bench`). Legacy config: 10 UNet passes, about 0.08 s/slice. |
| **Determinism** | Stochastic when `eta > 0`; `seed` makes a run reproducible (same call sequence, same device). Over seeds 0–4 on the 126-slice test split, max-Dice is 0.7085–0.7113 (see tutorial §6). |
| **Dependencies** | `huggingface_hub>=0.16.0` (added to `tools/requirements.txt`) and `pyyaml>=5.2` (already listed). `__init__` downloads, on first use, the MAD-AD repository `kaistpnp/madical_pnpxai` (UNet checkpoint `last.pt` 580 MB, plus code for `models`, `ldm`, `diffusion_x0`; the repo also holds two unused checkpoints, so a full snapshot is ~1.7 GB) and the VAE `farzadbz/Medical-VAE` (`VAE-Medical-klf8.pt`, 405 MB), both from huggingface.co, and adds the repository folder to `sys.path`. Network is needed unless the files are cached. |
| **Known limitations** | 1. Trained on healthy T2 slices only; FLAIR/T1/T1ce or non-registered inputs are out of distribution.<br>2. The VAE is unpickled with `torch.load` (full pickle); only load weights you trust.<br>3. Skipped in `tests/explainers/test_explainers_robustness.py`: that test feeds 3-channel ImageNet images to every explainer, which MadXai cannot take.<br>4. About 24× slower than the 0.1.x configuration. Lower `n_samples` for previews; the Dice cost of that has not been measured for the default configuration.<br>5. The reported numbers come from one 126-slice BraTS test split; there is no external validation set. |
| **Maintainer** | Jangho Park, KAIST |
