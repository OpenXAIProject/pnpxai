| **Class** | `pnpxai.explainers.AE` |
| **Category** | Relevance-based (feature-seeded Attribution Equilibrium); registered in `RELEVANCE_BASED_EXPLAINERS`. |
| **Backend** | Custom: PyTorch `torch.fx` graph execution and `torch.autograd.grad`, with AE propagation rules ported from the reference implementation. On VGG16, AlexNet, ResNet18/50, DenseNet121 and Inception v3 at `ratio` 1, 1.5 and 2, outputs equal the official code (commit `b4eadf3`) to float64 round-off wherever the official output is finite. |
| **Explanation type** | `attribution`; signed relevance. Positive and negative values are opposing contributions under AE's rule, not probabilities or differences from a baseline. |
| **Supported modules** | `Convolution` |
| **Modalities** | Image only. AE is included in `ImageModality.EXPLAINERS` and excluded from Text and TimeSeries; VQA's Image/Text intersection therefore does not recommend it. |
| **Model constraints** | White-box, differentiable image classifier that can be traced by `torch.fx`; return one logits tensor shaped `(B, classes)`. The selected feature layer must produce a spatial `(B, K, Hf, Wf)` tensor connected to the image. Its ancestors require implemented AE rules. The classifier after it needs ordinary autograd only. ResNet stages/block outputs are supported; internal layers of encapsulated residual blocks are not selectable. Standard feature-layer defaults cover VGG, AlexNet, ResNet, DenseNet, and Inception; a generic model defaults to its last Conv2d. An architecture match alone does not establish graph compatibility. torchvision's pretrained Inception v3 and GoogLeNet enable `transform_input`, whose scalar arithmetic has no AE rule: set `model.transform_input = False` and normalize inputs with mean and std 0.5 instead, which gives the same logits. |
| **Input** | Nonempty floating-point `Tensor(B, C, H, W)` on the model's device, with model-appropriate normalization performed outside the model. `forward_arg_extractor` may return that tensor or a one-element tuple, which is unwrapped; multiple attributed inputs and integer token ids are unsupported. `additional_forward_arg_extractor` supplies extra positional forward arguments, without separate returned attributions; batch-first tensors among them are split per image. `targets=None` selects predicted classes; an integer scalar broadcasts, or an integer vector of length `B` selects per-image classes. Each image is explained on its own, as in the reference, so a batch returns the same maps as explaining its images one by one. |
| **Output** | A single signed tensor shaped exactly like the image `(B, C, H, W)`, on the same device and floating-point dtype in the supported execution path; the default tutorial returns `float32`. Detached from autograd. `layer` changes the starting feature map, not the final output shape. No channel pooling, heatmap normalization, tuple output, baseline-relative completeness, or guarantee that relevance sums to the class logit. |
| **Hyperparameters** | `model: nn.Module` — required classifier; the base constructor selects evaluation mode.<br>`layer: Optional[Union[str, nn.Module]] = None` — module path/object or FX node name; defaults to VGG's activation before final feature pooling, AlexNet/DenseNet `features`, ResNet `layer4`, Inception `Mixed_7c`, otherwise the last Conv2d.<br>`ratio: float = 2.0` — finite value in `[1, 2]`; modulates positive relevance on applicable paths, with no iteration-count change; validated at attribution time.<br>`forward_arg_extractor = None` — optional callable extracting the image tensor from a batch.<br>`additional_forward_arg_extractor = None` — optional callable extracting extra positional model arguments. |
| **Tunables** | `ratio` → `float(low=1.0, high=2.0)`. |
| **Injected defaults** | Accepts `layer`, `forward_arg_extractor`, and `additional_forward_arg_extractor`. Image AutoExplanation constructs AE with `layer=None`, `ratio=2.0` and does not inject a layer or these extractors. Its attempted `baseline_fn` and `feature_mask_fn` injections are intentionally skipped by `hasattr`: AE has neither attribute and requires neither. Configure custom extractors manually when needed. |
| **Post-processing** | Use `channel_dim=1` for RGB images, yielding `(B, H, W)`. A signed channel sum with identity normalization preserves the reference AE view; the tutorial supplies `SignedSum`. Built-in `l1norm` sums absolute channel values for magnitude metrics. `sumabs` takes the absolute value after channel summation, allowing cancellation; `sumpos` clips the channel sum, while `possum` clips channels before summation. Positive-only and magnitude pooling both discard sign information. `identity` leaves channels intact. Generic `minmax` normalization is unsuitable for constant maps because its denominator is zero; select identity normalization for that case. |
| **Metrics** | `MuFidelity`, `AbPC`, `MoRF`, `LeRF`, and `Complexity` accept appropriately post-processed image maps. AbPC/MuFidelity/LeRF: higher is better; MoRF/Complexity: lower is better. Magnitude-map scores do not validate the correctness of attribution signs. `Sensitivity` requires a callable applying the same post-processing to recomputed maps; passing the raw AE object while supplying pooled reference maps mixes representations and may silently broadcast. It re-invokes attribution on its `n_iter` perturbed copies, each costing one AE explanation. The runnable tutorial verifies AbPC and Complexity and omits unadapted Sensitivity. |
| **Cost** | Per image; a batch is explained image by image, so it costs `B` times as much. One full model forward plus one classifier-head vector-Jacobian product to seed the feature map; additional local work depends on its ancestors. Each propagated feature Conv2d uses three bias-free convolution recomputations and four input VJPs; an input-layer Conv2d uses three recomputations and one joint VJP covering three convolution adjoints. Pooling uses one recomputation and one VJP. Encapsulated ResNet/DenseNet blocks add a forward replay for their caches; BatchNorm uses algebra. `ratio` changes values, not these counts. Intermediate storage grows with activation sizes; FX tracing and initial block setup add startup cost.<br>Measured: **257.0 ms/sample**, warmed three-repeat mean, pretrained ResNet18, `layer='layer4'`, `ratio=2.0`, batch 1, RGB 224×224, Windows CPU Intel Core i7-14700, two intra-op threads, PyTorch 2.8.0/TorchVision 0.23.0. **810.7 MiB process peak working set**, including Python/framework imports, model, data, warm-up, and measured calls; this is not incremental AE allocation or GPU memory. With the same model and settings under PyTorch 2.6.0/TorchVision 0.21.0 (`--bench`): **338.3 ms/sample** on Linux CPU Intel Xeon Gold 6226 with two intra-op threads, and **53.8 ms/sample, 0.25 GiB peak allocated** on an NVIDIA Quadro RTX 6000. Figures vary with environment. |
| **Determinism** | The AE algorithm has no sampling. For a fixed evaluation-mode model, input, targets, layer, ratio, and deterministic kernels, repeated calls are deterministic. On CUDA, nondeterministic cuDNN kernels can change some maps noticeably, because AE's sign masks and safe divisions amplify tiny numerical differences; `pnpxai.utils.set_seed`, which the tutorials call, selects deterministic cuDNN kernels. Optuna search and randomized evaluation metrics have their own seeds and are separate from AE itself. |
| **Dependencies** | No AE-specific third-party package or weight download; uses the project's PyTorch runtime. `optuna>=3.1.0` is already in `tools/requirements.txt` for optimization. `AE.__init__` traces the supplied model and needs no network access. The tutorial's shared model loader downloads cached-on-reuse ResNet18 weights, `resnet18-f37072fd.pth`, approximately 44.7 MB from `download.pytorch.org`; [TorchVision documents the weights and transforms](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet18.html). Applicable upstream model/data terms govern those weights; no separate weight license is declared here. The tutorial reads existing local ImageNet samples. |
| **Known limitations** | 1. Supports implemented, traceable 2D image graphs, not arbitrary `Convolution` subclasses such as Conv1d/Conv3d, text, recurrent models, or general multimodal inputs.<br>2. Data-dependent control flow can prevent FX tracing; unsupported ancestors raise an error naming the node. Nonzero Conv2d padding modes, pooling indices, and general structured outputs are unsupported. SiLU, ReLU6, Hardswish, GELU, LayerNorm, stochastic depth, elementwise products (squeeze-and-excitation), `chunk`, and arithmetic with Python scalars have no rule, so torchvision's EfficientNet, MobileNet V2/V3, ConvNeXt, Swin, RegNetY, MaxViT and ShuffleNet raise at attribution time; its AlexNet, VGG, ResNet/ResNeXt/Wide ResNet, DenseNet, MNASNet, RegNetX and SqueezeNet run, as do Inception v3 and GoogLeNet without `transform_input`.<br>3. Cancellation or an absent relevance sign can produce zeros; safe division intentionally returns zeros where the reference divides zero by zero and returns NaN, as the official code does for some Inception v3 inputs at `ratio=2`.<br>4. Reference-specific ResNet and DenseNet branch behavior is retained. Linear retains reference `hedge()` identity behavior; seed at a convolutional feature map rather than the classifier output.<br>5. Input-layer detection defaults to the reference three-input-channel heuristic. The low-level Conv2d rule accepts an override, but the public AE constructor does not expose it; non-RGB first layers need an executor/rule adaptation for the bounded input rule.<br>6. Unadapted Sensitivity and min-max normalization of constant maps are unsuitable. Mixed precision is untested. |
